# 跑跑卡丁车道具系统运行逻辑详解

## 一、道具系统整体架构

### 1.1 系统模块划分

```
道具系统
├── 道具获取模块（ItemBox + GameItemManager）
├── 道具存储模块（ItemSlot）
├── 道具控制模块（ItemBasicController）
├── 道具实体模块（GoItem系列）
├── 道具参数模块（ItemParam系列）
└── 网络同步模块（ItemPacket）
```

### 1.2 核心类职责

| 模块 | 核心类 | 主要职责 |
|------|--------|----------|
| 获取 | ItemBox.cs | 道具箱碰撞检测、道具生成触发 |
| 获取 | GameItemManager.cs | 根据排名计算道具概率、生成道具 |
| 存储 | ItemSlot.cs | 管理道具槽位、触发道具使用 |
| 控制 | ItemBasicController.cs | 道具生命周期管理、状态机控制 |
| 实体 | GoItem*.cs | 具体道具行为实现 |
| 参数 | ItemParam.cs | 道具数据封装、网络传输 |

## 二、道具获取流程

### 2.1 道具箱碰撞检测（ItemBox.cs）

```csharp
触发流程：
1. OnTriggerEnter检测碰撞
2. 验证碰撞者是否为有效卡丁车
3. 调用GameItemManager生成道具
4. 发送GET_ITEM消息给对应玩家
5. 隐藏道具箱3秒后重新显示
```

关键代码逻辑：
- 碰撞层级：Item层
- 重生时间：3秒
- 碰撞验证：必须是有效的卡丁车索引

### 2.2 道具生成算法（GameItemManager.cs）

#### 概率计算规则：
1. 获取当前玩家排名
2. 根据游戏人数选择概率表
3. 根据排名查询对应概率
4. 使用随机数生成道具

#### 概率数据结构：
```csharp
ITEM_PROBABILITY[玩家总数-1][道具类型, 排名]
```

#### 特殊规则：
- 最后一名玩家固定获得加速器（BOOSTER）
- 已完成比赛的玩家不获得道具

## 三、各道具运行逻辑

### 3.1 香蕉皮（GoItemBanana）

#### 状态机：
```
IGNORE(2秒) → IDLE → DESTROY
```

#### 运行逻辑：
1. **初始化**：
   - 在使用者身后生成
   - 向下射线检测地面高度
   - 开启2秒自伤保护期

2. **碰撞检测**：
   - 检测碰撞体名称必须为"kart_body"
   - 忽略自伤保护期内的使用者
   - 忽略网络玩家（GoNetKart）

3. **效果触发**：
   - 发送APPLY_ITEM消息
   - 使目标打滑失控
   - 销毁香蕉皮对象

### 3.2 UFO（GoItemUFO）

#### 状态机：
```
FIRE(0.5秒) → START(1秒) → PLAY(3秒) → END(0.5秒) → DESTROY
```

#### 运行逻辑：
1. **发射阶段**（FIRE）：
   - 在发射者上方显示UFO
   - 播放发射动画

2. **追踪阶段**（START→PLAY）：
   - 移动到目标玩家上方
   - 持续3秒减速效果

3. **结束阶段**（END）：
   - 播放消失动画
   - 清除减速效果

### 3.3 恶魔（GoItemDevil）

#### 状态机：
```
USE → DESTROY
```

#### 运行逻辑：
1. **目标选择**：
   - 可同时影响最多6个玩家
   - 通过位掩码标记目标

2. **效果应用**：
   - 持续5秒控制干扰
   - 1秒准备时间
   - 群体失控效果

3. **动画表现**：
   - 在发射者上方1.8单位显示
   - 播放恶魔动画效果

### 3.4 水导弹（GoItemWaterMissile）

#### 状态机：
```
FIRE(发射) → APPROACH(接近) → EXPLORE(爆炸) → DESTROY
```

#### 运行逻辑：
1. **AI目标处理**：
   - 延迟1-2秒自动命中
   - 直接应用减速效果

2. **玩家目标处理**：
   - 显示3枚导弹UI
   - 等待玩家点击防御
   - 防御窗口时间2秒

3. **防御机制**：
   - 成功防御所有导弹获得护盾
   - 失败则受到减速效果

4. **设备适配**：
   - iPhone坐标：[(100,350), (384,350), (284,200)]
   - iPad坐标：[(150,350), (612,350), (384,200)]

### 3.5 水炸弹（GoItemWaterBomb）

#### 状态机：
```
FIRE → FALL → EXPLORE → DESTROY
```

#### 运行逻辑：
1. **投放位置计算**：
   - 前方200单位距离
   - 基于赛道平面高度

2. **爆炸检测**：
   - 范围伤害判定
   - 通过碰撞器触发

3. **效果应用**：
   - 范围内所有卡丁车减速
   - 播放爆炸特效

### 3.6 水苍蝇（GoItemWaterFly）

#### 状态机：
```
FLY → EXPLORE → DESTROY
```

#### 运行逻辑：
1. **飞行轨迹**：
   - 使用贝塞尔曲线计算
   - 抛物线飞行路径
   - 停留0.4秒，飞行2秒

2. **追踪算法**：
   - 自动锁定目标位置
   - 预判目标移动

3. **效果触发**：
   - 命中后干扰视野
   - 爆炸特效

### 3.7 翻转（GoItemFlip）

#### 状态机：
```
FIRE → DESTROY
```

#### 运行逻辑：
1. **群体攻击**：
   - 最多影响6个玩家
   - 瞬间生效

2. **控制翻转**：
   - 持续5秒
   - 1秒准备时间
   - 左右控制反向

## 四、道具使用控制

### 4.1 槽位管理（ItemSlot）

#### 槽位配置：
- 最大槽位数：3
- 冻结机制：防止连续使用
- 平台差异：iPad版本2个槽位

#### 使用流程：
1. 检查槽位冻结状态
2. 验证道具是否存在
3. 创建道具参数
4. 发送使用消息
5. 执行道具效果
6. 网络同步
7. 更新UI显示

### 4.2 消息系统

#### 消息类型：
- GET_ITEM：获得道具
- USE_ITEM：使用道具
- APPLY_ITEM：应用道具效果

#### 消息传递：
```
MonoBehaviourExCenter → 目标对象 → 效果处理
```

## 五、网络同步机制

### 5.1 同步数据包

#### ItemPacket内容：
- 道具类型（GameItem）
- 使用时间戳
- 目标玩家ID
- 使用位置
- 使用朝向
- 道具参数

### 5.2 同步流程

1. **本地使用**：
   - 创建ItemPacket
   - 执行本地效果
   - 发送到服务器

2. **服务器验证**：
   - 验证使用合法性
   - 广播给其他玩家

3. **远程显示**：
   - 接收道具包
   - 显示远程效果
   - 不执行碰撞检测

## 七、设计特点

### 7.1 平衡性设计
- 排名越靠后，获得强力道具概率越高
- 最后一名保证获得加速器
- 道具之间存在克制关系

### 7.2 交互设计
- 水导弹的主动防御机制
- 道具使用的视觉反馈
- 多平台输入适配

### 7.3 技术实现
- 状态机模式管理道具生命周期
- 消息系统解耦模块通信
- 对象池优化性能

# 《鬼灭之刃》题材小游戏 —— 英雄卡池 / 抽卡系统详细设计文档

本文档详细描述游戏内“英雄卡池/抽卡系统”的功能结构、数据设计、概率机制、保底策略、经济循环、UI/交互、运营支持、风控与分析方案。适用于策划、程序、数据、运营与美术协同开发。

---

## 1. 系统定位与目标
- 核心功能：提供主要角色（鬼杀队成员 / 鬼）获取渠道，驱动收藏与战力成长。
- 设计目标：
  1. 新手期快速建立基础阵容（保障正反馈）。
  2. 中期通过限定/活动卡池引导持续参与。
  3. 保底+碎片机制降低挫败感。
  4. 多种货币/福利分层，兼顾 F2P 与付费玩家体验。
  5. 概率透明、易理解、可拓展。

## 2. 卡池类型（Banners）

| 类型          | 适用阶段 | 是否常驻 | 主要资源 | 特征 | 下架规则 |
|---------------|----------|----------|----------|------|----------|
| 新手卡池       | 账户前 N 次（如30抽） | 否 | 钻石/新手券 | 折扣(每10抽消耗减少) + 必得≥SR + 第30抽保底指定SSR | 完成后消失 |
| 常驻标准卡池   | 全阶段   | 是 | 钻石/常驻券 | 全部非限定角色 | 永久 |
| 限定活动卡池   | 中后期   | 否 | 钻石/限定券 | 限定SSR概率 UP，独立保底计数 | 活动结束下架（可返场） |
| 复刻限定卡池   | 中后期   | 否 | 钻石/限定券 | 历史热门角色返场 | 排期 |
| 精选轮换卡池   | 中后期   | 否 | 钻石 | 当期2～3个SSR精选（权重调整） | 周 / 双周轮换 |

## 4. 概率与保底机制

### 4.1 基础概率（常驻示例）
- 单抽期望：SSR 2.00%，SR 18.00%，R 80.00%。
- 10连保证：至少 1 个 ≥ SR（若未出则将一张 R 替换为 SR）。

### 4.2 有限卡池概率提升（活动SSR UP）
- 常驻 SSR 池拆分：UP SSR（1.2%） + 其他 SSR（0.8%）=2.0%。
- 若出现 SSR：60% 概率为 UP，40% 为其他 SSR（或直接按上面拆分）。

### 4.3 保底体系（双层 Soft + Hard）
| 类型        | 配置示例                    | 描述 |
|-------------|-----------------------------|------|
| SR 小保底   | 每10抽 | 若前9抽无SR+，第10抽强制≥SR |
| SSR Soft    | 从第50抽开始 SSR 概率递增：Base 2% + 每次未中 +0.5% | 上限 100抽时若仍未中则进入 Hard |
| SSR Hard    | 100抽必定出 SSR             | 归零保底计数 |
| 限定定向保底 | 若出 SSR 但非UP，计入“歪”计数；歪 1 次后下次 SSR 必为 UP | 防多次歪出非UP |

Soft 线性增长公式：
P_current = min(P_base + (pull_index - soft_start + 1) * increment, P_cap)
例如：第50~99抽增长段：第50抽概率=2%+0.5%=2.5%，第99抽概率=2%+(50*0.5)=27%（可按平衡调整）。

### 4.4 公示策略
- 前端展示：基础概率、UP角色详情、保底说明、历史抽取记录（最近20次）。
- 服务器输出可追溯日志（gacha_log），保障合规与运营核查。

## 6. 重复角色处理（Dup Conversion）

| 稀有度 | 首次获得 | 重复获得奖励（示例） | 说明 |
|--------|----------|----------------------|------|
| SSR    | 解锁角色本体 | 20 SSR碎片 + 50 光辉币 | 碎片用于升星（星级阶梯：40/80/160/...） |
| SR     | 解锁角色本体 | 10 SR碎片 + 10 光辉币 | SR碎片可合成指定 SR（消耗率） |
| R      | 解锁角色本体 | 5 R碎片              | R 碎片 100：1 合成 SR 碎片（可调） |

重复超出升星最大星级后：
- SSR：转换为光辉币加成（如原 20 碎片 → 10碎片 + 80光辉币）
- 提供“溢出自动转换”开关。

## 9. 抽卡流程（逻辑顺序）

1. 校验：卡池有效期、玩家资源充足、账户状态（未封禁）。
2. 读玩家该池 pity 状态。
3. 计算 SSR 实际概率：
   - 若达 hard pity：直接产出 SSR。
   - 否则：Base + 增幅（若经过 soft_start）。
4. Roll 稀有度（含 SR 10连兜底逻辑）。
5. 若 SSR：
   - 判定是否触发限定定向保底（若上一 SSR 歪 & directional_guarantee=true → 强制UP）。
   - 未触发则按 UP 权重二次 roll。
6. 得到角色ID：
   - 若重复 → 按重复转换规则生成碎片/光辉币。
   - 若首获 → 解锁角色并广播（可选公告）。
7. 更新 pity 计数：
   - 抽到 SSR：since_last_ssr=0；若非UP且 directional → last_ssr_up_fail=true，否则 false。
   - 抽到 SR：since_last_sr=0。
   - 其他：计数+1。
8. 写入日志：落库（异步队列）。
9. 返回结果（批量十连则打包数组）。
10. 触发运营钩子：任务进度（如“今日抽卡 X 次”）、活动积分、成就解锁。

## 11. 数值与平衡建议

### 11.1 SSR 获得期望
- 不含 Soft：期望 1/0.02=50 抽。
- 含 Soft + Hard（100）：真实期望 ≈ 55~60（取决于增幅参数）。
- 建议运营 KPI：核心 SSR 获取周期 ≤ 2 周活跃（结合免费资源≈30~40 抽 + 付费补足）。

### 11.2 免费资源投放（周）
| 来源 | 次数/周期 | 抽卡券折算 |
|------|-----------|-----------|
| 日常任务 | 7天 × 1 | 7 |
| 签到 | 平均 | 3 |
| 活动 | 周期性 | 5~10 |
| 成就/新手 | 前两周总计 | ~30 |
合计：首月免费≈60~80 抽（含钻石换算），支撑新手留存。

## 12. 反沉迷 / 风控与防刷

| 风险点 | 方案 |
|--------|------|
| 非法脚本批量调用 | 抽卡接口限频：单账号每分钟 ≤N 次；IP 维度黑名单阈值 |
| 重放攻击 | 请求附带一次性 nonce + 服务端签名验证 |
| 数据篡改 | 所有抽卡结果由服务端生成并签名，客户端仅展示 |
| 概率纠纷 | 服务器保留日志（pool_id, seed, roll_detail），可追溯 |
| 触发异常概率 | 实时监控 SSR 总产出/期望比值（超阈触发报警） |

## 16. 示例：一次十连过程（伪代码）

```
function doTenPull(player, pool_id):
  validatePool(pool_id)
  consumeResource(player, pool_id, 10)

  results = []
  for i in range(10):
    rarity = rollRarityWithPity(player, pool_id, i==9) // i==9: enforce SR pity if needed
    if rarity == SSR:
       char_id = rollSSR(player, pool_id)
       updateSSRStates(player, pool_id, char_id)
    else if rarity == SR:
       char_id = rollSR(pool_id)
       resetSRPity(player, pool_id)
    else:
       char_id = rollR(pool_id)
    grantCharacterOrConvert(player, char_id)
    results.append({ "rarity": rarity, "char_id": char_id })
  persist(player)
  logGacha(player, pool_id, results)
  return results
```

## 17. 风险与调优建议
| 问题 | 现象 | 调整手段 |
|------|------|----------|
| 早期流失（未出SSR） | 7日内未见SSR | 下调 Soft 起点（50→40）或新手池保底提前 |
| SSR 通胀 | 战力曲线失控、复合付费下降 | 限制 SSR 产出：Soft 增幅降低/兑换成本提高 |
| 重复过多挫败 | 玩家社群负面反馈 | 加入 Wish List 或定向保底阈值缩短 |
| 限定池过长 | 付费疲劳 | 控制活动周期（10-14天），减少同时开放池数量 |
| 碎片囤积 | 延迟消耗 | 引入高阶升星需求/皮肤碎片合成 |

## 18. 公示文案（示例草案）

> 抽卡概率（四舍五入显示）：
> - SSR：2.00%（活动UP SSR 总计 1.20%，其他 SSR 0.80%）
> - SR：18.00%
> - R：80.00%
> 每 10 次必得 1 个或以上 SR。
> 自第 50 抽后 SSR 出现概率逐步提升，最晚第 100 抽必定出现 SSR。

> 抽卡记录与概率受服务器控制，客户端展示仅供参考。

## 20. 概率模拟（开发自测建议）
- 脚本模拟 N=1,000,000 次抽卡：
  - 统计 SSR 相对偏差（应 < ±0.2%）
  - 统计 SSR 平均抽数期望（与理论差距 <5%）
  - 统计保底前出 SSR 比例（衡量早期快感）
  - 统计歪后下次是否 100%UP（验证方向保底）

## 21. 安全与兼容性
- Seed 生成：后端基于安全随机数（/dev/urandom 或 crypto PRNG）。
- 不将 seed 暴露客户端。
- 接口防刷：抽卡请求签名 + 限流（令牌桶）。
- 容灾：抽卡事务性（扣资源 + 结果写日志 + 回包），失败回滚。

该抽卡系统在保障“概率透明 + 保底缓冲 + 重复回收”基础上建立可演进结构，通过多层池与资源体系形成循环驱动力，可平衡 F2P 与付费用户体验。后续可依据玩家数据调整 Soft / Hard 参数与资源投放节奏，以维持健康经济与长线留存。

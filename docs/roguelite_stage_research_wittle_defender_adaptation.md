## 1. Roguelite 核心特征拆解（通用基因）
| 维度 | 通用做法 | 在塔防 / 波次类的体现 | 价值 |
|------|----------|------------------------|------|
| 运行（Run）随机性 | 地图/事件/奖励半随机 | 每波敌人组合、Buff、事件房 | 提升复玩性 |
| 增益（Relic/Perk） | 临时/长效被动加成 | 波间选择“遗物/增幅卷轴” | 构建差异化 Build |
| 分支路径 | 多节点路线选择 | 下波走 A（金币多）或 B（风险大） | 风险-收益决策 |
| 资源权衡 | 生命/货币/时间二选 | 消耗当前奖励换高阶 Buff | 增加紧张度 |
| 永久元进度 (Meta) | 运行外解锁 | 解锁新遗物池 / 角色初始加成 | 中长期留存 |
| 可预期随机（Seed） | 显示或分享种子 | 竞速/挑战模式 | 竞技与社区传播 |

## 5. 运行（Run）边界定义（适配方案）
| 项目 | 首发可行轻量版 | 完整版（后期） |
|------|----------------|---------------|
| Run 场景 | 独立“试炼模式”入口 | 主线章节可开启“随机化模式” |
| 结束条件 | 通过固定 10 波或角色全灭 | 无限 → 排行榜结算 |
| 构筑增益数量 | 每 2 波选 1 次（共 4~5 次） | 每波有微增益 + 特殊事件房 |
| 遗物稀有度 | 统一权重 | 分级：普通 / 稀有 / 传奇 |
| 奖励 | 呼吸精魄 + Rogue 代币 | 代币兑换专属“流派札池” |
| 保存 | 退出即弃（不保存中途） | 云快照 / 恢复功能 |

## 7. 随机构建算法（轻量方案）
1. 初始化随机种子：Seed = hash(player_id + server_day + run_attempt_no)
2. 生成波次：
   - 基础模板库(按章节段位) → 按 Seed 洗牌 → 前 N 条取用
3. 每 2 波触发一次“增益选择”：
   - 从遗物池按稀有度权重抽取 3 份（去重、避免互斥组合）
   - 使用热度阻尼：24 小时内被全服选择率过高的遗物抽取权重 -X%
4. Elite 可选波：
   - 第 4 或第 6 波前给分支：A 正常波 / B Elite 波（掉落提升 + 增益多 1 选 1）
5. Boss 波：
   - 固定阶段 + 动态附加一个随机“环境异变”Modifier（例：敌人 HP +15% 或 我方冷却 +1 初始）
6. 奖励结算：
   - 基础 + Elite 计数加成 + 未选择 Elite 的补偿（避免极端 Bad Luck）。

## 9. 与现有“主线章节”融合策略
| 阶段 | 融合方式 | 不破坏主线的策略 |
|------|----------|------------------|
| V1 | 独立入口“试炼模式” | 不占章节节点，不影响主线掉落比 |
| V2 | 主线章节添加“随机化开关” | 开启后禁用扫荡，额外 Rogue 代币 |
| V3 | 替换部分精英关为“随机事件关” | 保持每日次数逻辑，奖励平行替换 |
| V4 | 章节 Boss 添加随机 Modifier 池 | 显示即将出现的变体加提示 |
| V5 | 周期赛季（Seed 固定一周）排行榜 | 奖励以头像框 / 外观为主，避免破坏经济 |

## 10. 数值与平衡基线建议
| 项 | 初始建议 | 调整判据 |
|----|----------|----------|
| 10 波 Run 完成率 | 首周中位玩家 ≥65% | <55%：削弱中段敌人 HP；>80%：增强第 7+ 波 |
| 平均遗物选择次数 | 4~5 次 | <4：波间触发频率太低 |
| 单 Run 平均时长 | 6~8 分钟 | >10 分钟：减少波数或提高击杀效率 |
| Elite 选择率 | 40~55% | <30%：加强 Elite 奖励；>70%：下调奖励 |
| 传奇遗物出现率 | 0.5~1.0% / 次选择 | 玩家讨论热度 / 留存数据 |

## 12. 风险与防范
| 风险 | 描述 | 预防 |
|------|------|------|
| 运行掉线利用 | 反复中止刷前几波奖励 | 中途未到保存点不发放奖励；结算一次性 |
| 过强遗物导致主线失衡 | 玩家用 Rogue Buff 进入普通关卡 | 遗物仅在 Run 内有效，出 Run 清空 |
| 数值爆炸 | 叠层类遗物无限增长 | 设叠层上限或递减收益 |
| 随机过度挫败 | 玩家连遭坏随机放弃模式 | 引入“偏好权重”与失败补偿 token |
| 冗余开发 | 过早做复杂事件系统 | 分阶段：先 Buff 选择，再加事件，再加分支地图 |

## 13. 迭代路线（推荐）
| 版本 | 核心交付 | 验证指标 |
|------|----------|----------|
| Rogue V1 | 独立 10 波 + 基础遗物选择 + 结算奖励 | Run 完成率 / 平均时长 |

| Rogue V4 | Seed 分享 + 每周排行榜 | 回流率 / 排行参与渗透 |
| Rogue V5 | 主线随机化开关 + 赛季池 | 主线活跃回升幅度 |

## 15. 示例：一次 10 波 Run 简图
波1：基础 → 波2：基础 → (选择 1/3 遗物) → 波3 → 波4(提示：可转 Elite) → 玩家选 Elite → 奖励+额外遗物选择 → 波5 → 遗物选择 → 波6 → 环境 Modifier 加入（敌HP+10%）→ 波7 → 波8（再给 Elite 分支）→ 波9 → 遗物选择 → 波10 Boss（随机环境异变）→ 结算。

## 16. 伪代码骨架（核心循环）
```
startRun(player):
  state = initRunState(seed, waves=10)
  while state.current_wave <= state.max_waves:
     waveCfg = buildWave(state)
     result = playWave(player, waveCfg, state.relics)
     recordWaveEnd(result)
     if !result.win: endRun(fail); break
     if isRelicChoiceWave(state): offerRelics(state)
     if isEliteBranchWave(state): handleEliteChoice(state)
     state.current_wave++
  if state.current_wave > state.max_waves: endRun(clear)

offerRelics(state):
  candidates = rollRelics(exclude=state.relics, count=3, rarityWeights)
  pick = playerChoose(candidates)
  applyRelic(state, pick)
```

## 19. 结论
在现有主线关卡体系基础上引入 Roguelite 元素，应当采取“独立 Run → 轻量增益 → 精英分支 → 数据验证 → 再与主线融合”的渐进式路径。关键是先搭建：  
(1) 可循环的随机增益选择  
(2) 波次生成与权重参数可调  
(3) 监控数据回流机制  
再逐步扩展事件、分支路径与赛季化运营。  
上述方案与鬼灭主题自然结合（呼吸札、遗物、诅咒札等命名），减少违和感并增强 IP 代入。
